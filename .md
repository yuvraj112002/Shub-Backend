# OTP 
✅ When to Verify OTP in Your Project
🔁 Option A: During Account Creation (Recommended for signup email verification)
Flow:

✅ User submits registration form

✅ Server saves the user with isVerified: false and sends an OTP

🔐 User sees an OTP input screen on frontend (instead of logging in)

✅ User enters OTP → it hits /verify-otp endpoint

✅ If OTP is valid, mark isVerified: true

🔓 User is now allowed to log in

Purpose: Only verified users can use the platform (prevents fake accounts)

# ✅ Final OTP Email Verification Flow (Using Cookie – Option 2)

This document describes a secure and user-friendly OTP-based email verification flow where the user's email is stored in an HttpOnly cookie, so they don't need to re-enter it when verifying the OTP.

---

## 🔁 Flow Overview

### Step 1: User Registers

**Frontend:**
- Sends: `name`, `email`, `password`, `phoneNumber`

**Backend:**
- Creates user with `isVerified: false`
- Generates a 6-digit OTP:
  ```js
  const otp = Math.floor(100000 + Math.random() * 900000).toString();
Sets:

```js
user.otp = otp;
user.otpExpires = Date.now() + 5 * 60 * 1000; // 5 min expiry
Sends OTP to the user's email using Nodemailer

Stores the email in a secure HttpOnly cookie:
```
```js
res.cookie('verify_email', email, {
  httpOnly: true,
  secure: false, // true in production
  sameSite: 'lax',
  maxAge: 10 * 60 * 1000
});
```

Step 2: User Enters OTP
Frontend:

Shows only an OTP input field

Sends request:

  "otp": "123456"

Backend:

Reads email from the cookie:

const email = req.cookies.verify_email;
Finds user by:

{
  email,
  otp,
  otpExpires: { $gt: Date.now() }
}
If valid:

Sets isVerified = true

Clears otp and otpExpires

Clears verify_email cookie

Issues JWT token and stores in HttpOnly cookie:

res.cookie('token', jwtToken, {
  httpOnly: true,
  maxAge: 24 * 60 * 60 * 1000 // 1 day
});
Response:
json
{
  "message": "Email verified. Logged in."
}
🔐 Security Features
Feature	Description
HttpOnly cookie	Email is not accessible via JavaScript
OTP with expiry	OTPs are time-limited (e.g., 10 minutes)
No email re-entry	Users don’t re-enter email, improving UX
JWT login after verify	Immediate login on successful verification
Clear cookies after use	Prevents reuse of old verification sessions

💡 Recommendations
Store OTP as hashed in DB (e.g., bcrypt.hash(otp))

Limit OTP attempts per user/IP

Add a /resend-otp endpoint with cooldown (e.g., 60 seconds)

In production, use secure: true for cookies (HTTPS only)
